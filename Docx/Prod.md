# Проект создания приложения Nexora

## 1. Назначение проекта

Приложение Nexora - это корпоративный сайт веб-студии с управляемым контентом, публичной клиентской частью, административной панелью и API для вывода страниц, проектов, блога и заявок.

Цель проекта - создать единое приложение, в котором публичный сайт работает быстро и удобно для пользователя, а администратор может управлять страницами, SEO-данными, проектами, публикациями и заявками без прямого изменения кода.

## 2. Технологический стек

Backend:
- PHP 8.2.
- Laravel 10.
- Laravel Nova 5.
- Laravel Sanctum.
- MySQL 8.

Frontend:
- Vue 3.
- Vue Router.
- Vite.
- Axios.
- CSS для landing-интерфейса.

Инфраструктура:
- Docker Compose.
- Nginx.
- PHP-FPM.
- MySQL.
- phpMyAdmin.

## 3. Основные модули приложения

### 3.1. Публичный сайт

Публичный сайт должен открываться через Laravel и рендериться как Vue-приложение.

Основные страницы:
- Главная страница.
- Страница тарифов.
- Страница проектов.
- Детальная страница проекта.
- Новости.
- Детальная страница новости.
- Статьи.
- Детальная страница статьи.
- Универсальные CMS-страницы по slug.

Laravel отвечает за начальный HTML, SEO-мета-теги и подключение frontend-сборки через Vite. Vue отвечает за маршрутизацию, получение данных из API и отображение интерфейса.

### 3.2. API

API должно отдавать данные для публичного Vue-приложения.

Основные группы endpoint-ов:
- `/api/page/navigation` - навигация сайта.
- `/api/page/footer` - данные футера.
- `/api/page/home` - данные главной страницы.
- `/api/page/pricing` - данные страницы тарифов.
- `/api/page/{slug}` - универсальная CMS-страница.
- `/api/projects` - список проектов.
- `/api/projects/{slug}` - детальная страница проекта.
- `/api/news` - список новостей.
- `/api/news/{slug}` - детальная страница новости.
- `/api/articles` - список статей.
- `/api/articles/{slug}` - детальная страница статьи.
- `/api/orders` - отправка заявки.

Ответы API должны быть пригодны для прямого использования во Vue-компонентах.

### 3.3. CMS и CRM

Административная часть строится на Laravel Nova.

Через Nova необходимо управлять:
- страницами сайта;
- контентными блоками страниц;
- SEO-заголовками и описаниями;
- проектами;
- изображениями проектов;
- тегами проектов;
- новостями и статьями;
- заявками пользователей;
- API-интеграциями;
- пользователями и ролями.

### 3.4. SEO

Приложение должно поддерживать:
- индивидуальные title и description для страниц;
- canonical URL;
- Open Graph meta-теги;
- Twitter Card meta-теги;
- sitemap.xml;
- человекопонятные URL;
- корректные slug для страниц, проектов и публикаций.

### 3.5. Заявки

Пользователь должен иметь возможность отправить заявку с сайта.

Требования:
- endpoint `/api/orders`;
- валидация входящих данных;
- ограничение частоты отправки;
- сохранение заявки в базу данных;
- возможность просмотра заявок в Nova;
- логирование ошибок отправки уведомлений, если внешняя отправка недоступна.

## 4. Модель данных

Основные сущности:
- `User` - пользователь системы.
- `UserRole` - роль пользователя.
- `Page` - CMS-страница.
- `Project` - проект в портфолио.
- `ProjectImage` - изображение проекта.
- `Tags` - тег проекта.
- `ProjectTag` - связь проекта и тега.
- `BlogPost` - новость или статья.
- `Order` - заявка с сайта.
- `ApiIntegration` - настройки внешних интеграций.

Связи должны обеспечивать:
- привязку проектов к изображениям;
- привязку проектов к тегам;
- разделение публикаций на новости и статьи;
- управление активностью и порядком вывода материалов;
- хранение SEO-данных для страниц и публикаций.

## 5. Frontend-архитектура

Frontend строится как Vue 3 приложение.

Основные требования:
- маршрутизация через Vue Router;
- загрузка данных через Axios;
- разделение API-клиентов по модулям;
- переиспользуемые компоненты состояния загрузки и ошибки;
- отдельные компоненты страниц;
- отдельные layout-компоненты для header и footer;
- поддержка HMR в режиме разработки через Vite.

Основные Vue-страницы:
- `IndexPage.vue`;
- `PricingPage.vue`;
- `ProjectsPage.vue`;
- `ProjectViewPage.vue`;
- `NewsPage.vue`;
- `ArticlesPage.vue`;
- `BlogPostViewPage.vue`;
- `GenericPage.vue`.

## 6. Backend-архитектура

Backend должен быть разделен на:
- маршруты публичного сайта;
- API-маршруты;
- контроллеры страниц;
- контроллеры проектов;
- контроллеры блога;
- контроллер заявок;
- модели доменной области;
- Nova-ресурсы;
- сервисы интеграций.

Laravel должен отдавать единый входной шаблон для публичных страниц, а Vue должен брать данные через API.

## 7. Docker-окружение

Проект должен запускаться через Docker Compose.

Сервисы:
- `app` - PHP-FPM, Laravel, Node/Vite;
- `nginx` - веб-сервер;
- `db` - MySQL 8;
- `phpmyadmin` - управление базой данных.

Основные порты:
- `80` - публичный сайт через Nginx;
- `5173` - Vite dev server;
- `8102` - MySQL на хосте;
- `8080` - phpMyAdmin.

Для разработки на Windows через Docker необходимо включить polling в Vite и разрешить CORS для домена `http://nexora.loc`.

## 8. Режим разработки

Запуск окружения:

```powershell
docker compose up -d --build
docker compose exec app php artisan migrate
docker compose exec app php artisan db:seed
```

Запуск frontend-разработки:

```powershell
docker compose exec app npm run watch
```

Сайт открывается по адресу:

```text
http://nexora.loc
```

Адрес `http://localhost:5173` используется только как Vite dev server. Это не адрес сайта.

Остановка watcher:

```text
Ctrl + C
```

Production-сборка frontend:

```powershell
docker compose exec app npm run build
```

## 9. Тестирование

Проект должен иметь автоматические тесты для ключевых сценариев:
- доступность публичных страниц;
- работа API навигации и футера;
- получение CMS-страниц;
- получение проектов;
- получение новостей и статей;
- отправка заявки;
- генерация sitemap;
- работа интеграций;
- проверка моделей и связей.

Основная команда запуска:

```powershell
docker compose exec app php artisan test
```

## 10. Требования к качеству

Код должен соответствовать требованиям:
- понятное разделение frontend и backend-логики;
- отсутствие бизнес-логики во Vue-компонентах сверх отображения и вызова API;
- валидация всех входящих данных на backend;
- единый формат API-ответов;
- отсутствие сгенерированных runtime-файлов в git;
- документация команд запуска и сборки;
- стабильная работа Docker-окружения на Windows.

Первая рабочая версия должна включать:
- публичный сайт на Laravel + Vue;
- главную страницу;
- проекты и детальные страницы проектов;
- новости и статьи;
- универсальные CMS-страницы;
- форму заявки;
- Nova-админку для управления контентом;
- SEO-мета-теги;
- sitemap.xml;
- Docker Compose окружение;
- базовый набор тестов.

После первой версии можно добавить:
- расширенные роли и права доступа;
- email-уведомления о заявках;
- интеграции с CRM;
- интеграции с аналитикой;
- расширенную фильтрацию проектов;

- автоматический деплой;
- CI-проверки тестов и сборки.

## 13. Критерии готовности

Проект считается готовым, если:
- сайт открывается через `http://nexora.loc`;
- публичные страницы корректно получают данные из API;
- администратор может управлять контентом через Nova;
- заявки сохраняются в базе данных;
- frontend собирается командой `npm run build`;
- режим разработки работает через `npm run watch`;
- тесты проходят без ошибок;
- Docker-окружение запускается одной командой;
- документация содержит актуальные команды запуска, разработки и тестирования.
